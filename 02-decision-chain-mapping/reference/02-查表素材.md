## 一、五维推断规则表

**四列信号表**：定档先查本表四列，再回 `reference\02-决策链破译与五维决策地图.md` 核对档位表原文（锚点仍引用标准口径，不改原文）。

**置信度判定（全表通用三级，呼应 SKILL.md §5.4）**：高=两条以上独立来源印证；中=单一内线来源/间接转述；低=未经核实的传闻或 AI 推测（低置信度只进 L2"待验证假设"区）。

| 维度 | 典型信号 → 档位锚点（标准口径） | 置信度判定提示 | 去哪验证（区分性验证问题） |
|---|---|---|---|
| **对我方态度**（五档） | 五维表五档的具体表现定义；"支持：收到压力时会退缩"；下属态度传导=组织领导意志而非个人情绪 | 冷淡起点事件须 ≥2 独立来源印证，否则降中 | 冷淡/变化起点对应什么事件？竞品当时在做什么？他本人提过具体不满吗？ |
| **马斯洛需求** | 安全需求=谨慎中立、不出头、怕事躲事；自我实现=关注业务突破与个人成就；归属需求=是谁的心腹、维领导马首是瞻 | 以本人行为与站队记录为准，传闻降低 | 他最近在争什么/怕什么？出事谁保他？他向谁表忠？ |
| **变革态度**（五档） | 五档表现定义；保守="有问题需要解决，但比较在意风险"；落后="不希望发生变化，不能接受风险" | 既往选型偏好有多项目记录支撑才给高 | 既往项目选型偏好？对标杆/创新项目什么反应？ |
| **决策关注点**（财务/技术/关系/业务） | 问价格账期付款=财务；问参数性能使用习惯=技术；问领导和其他部门意向=关系；问方案对业务的改变=业务 | 以本人原话/会议追问记录为准，转述降中 | 他开会反复追问什么？他提出的问题原文是什么？ |
| **联系紧密度**（四档） | 四档表现定义，**信息深度是关键**：隐私信息=联系深入；半公开=较多；公开=较少/没有 | 以最近单独接触事实为准，记忆模糊降中 | 现在能跟他聊到什么深度的信息？上次单独接触是什么时候、谈了什么？ |
| **角色归类**（接纳者/不满者/权力者） | 接纳者四类特征、不满者三类特征、权力者=拍板权所在；混合角色按 §1.10 | 角色判断须多方印证，单一中间人说法降中 | 他能提供什么层级才能知道的信息？他对现状/在位供应商有无公开或未公开的不满？这个项目谁签字？ |

用法（配合 SKILL.md §4.2 关联性自检）：需求=安全 ↔ 变革保守/落后；需求=自我实现 ↔ 变革战略、关注业务。关联不成立时视为矛盾信号，加问一轮再定档。

**派系字段口径**（SKILL.md §4.4 派系归属必填项）：填"这人是谁的人、背后哪个领导、属于哪一派"。判据：汇报关系与心腹程度（圈子相交关系）、公开场合的站队记录。填不出 → 标"待验证"并记入 L5 侦察任务，不静默留空；派系判断属敏感推断，按 SKILL.md §5.4 置信度三级标注。

## 二、内容警示清单（输出不得依赖以下残缺处）

1. **§1.8/§1.9 四个小标题不可读**：仅内容可读，小标题不可辨认——引用这两节时只引内容要点，不得杜撰小标题；
2. **主攻方向编号跳过（三）**：§3.3 补充编号为（一）（二）（四），无（三），不补编号；
3. **§1.7 第二个标题疑为"不愿见"**（待核实），按三档内容使用，输出按内容不依赖标题；
4. **页边批注一律 低置信度**：方法论页边批注（如整段派系笔记、"私下太早"、"孤立他，不投入"等）不作分析依据，仅可作"演练补充提示"附在输出末尾并注明置信度低。

### 4.2 分步打法表填写规范（固定输出格式配套，五条）

1. **每步一个目标角色**，步骤顺序沿接纳者→不满者→权力者路径递进（谁引荐谁，顺序即路径）；主攻+助攻+需转化/孤立者各有着落，不遗漏；
2. **核心逻辑列**回答"为什么先找他"——他的不满是什么、这步撬动的决策权重是什么；
3. **关键动作列**用 ①②③ 编号，写到可直接执行（见什么人、递什么材料、请对方做什么），末条给"达成什么信号算本步完成"；
4. **产出/里程碑列**给可交付物（情报摘要/调研报告/评审安排）或对方态度变化的里程碑；
5. 完整参照示例见 `reference\02-决策链破译与五维决策地图.md` §4.1"示例拆解：六步打法"表（S 公司案例，六行）——输出形态与其逐列对齐，只换客户内容。

## 五、产出维护时机四条（SKILL.md §六 配套）

人物档案模板与置信度分级以 `..\00-key-account-dev\reference\12-客户档案模型与模板.md` 为唯一权威源（独立模式按 SKILL.md 头部兜底块 L2 最简定义执行：逐人五维画像、带日期版本化、只追加不覆盖）。四条维护时机：

1. **新人物自动建册**：人物清单出现新名字 → 立即按 L2 模板在 `客户分析\<集团名-工厂名>\人物\<姓名-职务>.md` 建册，口头确认（"记下了：新增人物 XX，已建册"）；
2. **画像按日期版本叠加，旧版不删**：每次分析产生 `### YYYY-MM-DD 版` 新版本——变化性本身就是洞察；画像是判断、接触记录是事实，分开放；
3. **听说调离/退休 → 标【历史】**：画像标注"【历史】XX 年调离/退休，信息失效"，不删除（老关系网可能仍有价值），并提醒更新组织架构（L1）与追加事件（L4）；
4. **新旧矛盾不裁决**：追问澄清后追加新版本（防烂尾四规则见共享协议第四节）。

## 六、异常与降级速查（SKILL.md 原 §十 搬入）

任何依赖缺失**不报错中断**，按下表降级并向用户明示当前模式：

| 异常情形 | 降级动作 |
|---|---|
| 记忆层缺失 | 查工作区 `企业参数.md`；也没有 → 询问用户并标注"本次临时"；关键关系资源缺失记入前置缺口（SKILL.md §二） |
| 客户档案缺失 | 会话中自建目录与档案，标注"本环境无既有档案，本次新建" |
| 商机评估未跑/分级过期 | 提醒"先补分级再定投入强度"；用户选择继续 → 按实践口径强度推进并标注 |
| 方法论内容源断裂 | 明示"内容源缺失，仅能凭已有档案做粗分析"，不编造五维表条目，粗分析结论标注局限 |
| 低置信度情报堆积 | 只进 L2"待验证假设"区，不作建议唯一依据；先验证或给多分支预案（SKILL.md §5.4） |

原散落条款的完整表述见 SKILL.md §一/§五，本节为速查入口。
