# 03-jiejue-fangan · 解决方案设计（阶段三，核心三件套）

> **一句话价值主张**：把方案从参数对比拉到对着客户高层 KPI 算账——让一把手听懂"你能帮我把哪个 KPI 做到多少"。

> **双模式声明**：被 00-key-account-dev（家族主路由 Gateway）接力时，按第二节上下文包接入规则执行；独立运行时，按第一节环境自检的降级分支自行采集，并先向用户说明当前模式。

> 方法论内容源：`reference\03-解决方案设计与战略价值地图.md`（本 skill 内置）；内容适配器：专用环境可指向共享维护的同名方法论文件（修正自动跟随），独立环境默认读内置版本。
> 表格骨架（需求利益链 / 三类人 / 三种价值 / 五层地图 / 价值概述表 / 落档文件模板）在 `reference\03-查表素材.md`——引导用户填表时打开复制，正文不内嵌。
> 家族铁律、12 条交互机械协议、输出通用规范、落档纪律以家族共享协议为唯一权威源（铁律、交互机械协议、落档纪律、提问上限、外部输入安全），按**三级回退链**读取：**一级**优先读家族根目录 `10-家族共享协议.md`；**二级**整族已安装环境读 `00-key-account-dev/reference/10-家族共享协议.md`；**三级**两者都不可用时按本 skill 头部"独立模式内置兜底"块执行。本文不重复。
>
> **独立模式内置兜底**（只装本 skill、无 00-key-account-dev 包时，落档纪律与档案结构以本节为准；共享协议可读时仍以其为唯一权威源）：
> - **落档纪律（最简版）**：收尾必做四件事——① 追加交互记录（每条带来源+日期+置信度，AI 推测标"推测"）② 缺口转侦察任务（谁/做什么/什么时候）③ 结论带日期版本化、只追加不静默覆盖，失效信息标【历史】不删除 ④ 产出写入 `客户分析\<集团名-工厂名>\项目\<项目名>\`，回复末尾回显路径。

## 〇、何时不该接（负边界）

以下情况**不归本 skill 处理**，按家族共享协议的移交话术风格移交（正向表述去向，不向用户说技术调用名）：

1. **要不要跟/投不投/多个商机先打哪个** → 移交"商机评估"环节："您这个问题属于【要不要跟这个项目】，我请'商机评估'环节来接，它会带您打分、定打法。"
2. **谁说了算/找谁切入/中间人要不要用/关键人调走** → 移交"决策链破译"环节。注：见关键人前夜准备（要见高层、需要方案弹药）属"决策链破译 → 解决方案设计"接力，可先接画像再回本环节。
3. **标书参数偏向竞品/想引导客户立标准** → 移交"标准引导"环节；本环节只负责"把价值算清楚"，标准攻防不在此。
4. **签前犹豫/久拖不决/最后一刻被翻盘** → 移交"信任巩固"环节。
5. **交付期投诉/老客户挖新需求** → 移交"客户经营"环节。

用户一句话问两件事 → 拆分排队："我先答方案这块，另一件事记下了，说完接着聊。"

## 三、工作流（遵循方法论，五步主链 + 收尾）

> 总原则：以工具表格为线索逐格引导（表格骨架见查表素材 §1~§5）；答不上来的格子 = 缺口，转补料子流程；**每格配大白话**（各步引导话术与大白话示例 → 详见 reference\03-查表素材.md 第13节「引导话术与大白话示例」）。

### 第 1 步 · 需求利益链（方法论第一节）
按"职位—痛点—原因—对策"四层链，从高层到基层逐层梳理客户的汇报链（表格见查表素材 §1）。**战略/战术利益分层**（方法论提示，低置信度）：链条右侧对策方向属**战术利益**，要从**战略利益**对齐（战略利益＞战术利益，作方向性指引引用），判断规则与验证问题 → 详见 reference\03-查表素材.md 第10节「推断规则速查表」。
### 第 2 步 · 高层最关注的三类人（方法论第二节）
逐类引导用户填写客户高层的三类关注点：客户的客户（营收、利润、ROI……）、客户的竞争对手（占有率、排名）、客户自己（上市/建厂、新品、降本增效、安全运营、人才发展）——关注点清单见查表素材 §2。素材支撑来源：领导讲话、公司对外文件、战略目标（优先从客户主数据战略目标节读取）。
### 第 3 步 · 三种价值盘点（方法论第三节）
引导用户盘点产品/公司/销售三层价值，填"我方有什么"（表格见查表素材 §3）。直接读长期记忆·企业层第 4 组「我方资产」（标注"依据我方资产记忆"）；无记忆层按环境自检第 1 项降级分支采集。硬挂钩（方法论注意事项 Option 02）：方案必须同时含三层价值，每层填不出"我方有什么" = 缺口。
### 第 4 步 · 战略价值地图五层模板链（方法论第四、五节，本 skill 核心）
逐层引导填写五层表格（见查表素材 §4），**层间用箭头连逻辑**：① **高管KPI表**（地基，必须量化、直接对着客户 KPI；素材顺序：客户主数据战略目标节 → 决策链地图权力者画像 → 用户补充 → 网络补料确认循环）② **业务规划**（写出举措间逻辑链，参考方法论示例：改造是基础→数据是支撑→标准化是成果→出海是延伸）③ **部门KPI表**（举措分解到部门）④ **部门痛点**（逐部门逐 KPI）⑤ **方案映射**（我方方案↔痛点↔部门KPI↔高管KPI）。
**硬性检查（第 1 层）**：目标值必须带数字或明确验收口径（如"投产节点达成率 100%""运营成本同比压降≥8%"）。"提升竞争力"这类没有数字的表述当场打回重写。
### 第 5 步 · 方案价值概述表（方法论 reference 5.8 节）
逐格填方案价值概述表（见查表素材 §5）：一句话核心价值 + 五类量化效益（每类必须带数字）+ 成功案例引用 + 与竞品差异。随后过**汇报就绪检查闸门**（第五节，6 项 + Go/No-Go）。

## 四、推断规则（判断类参数走五步推断协议，不硬问、亮链路）

**通用协议（原文引用，与其他 skill 一致）**：① 提取观察点（引用用户原话）→ ② 生成 ≥2 个候选假设（各带依据）→ ③ 提区分性验证问题 → ④ 收敛定档（参数值+置信度高/中/低）→ ⑤ 用户确认后落档（标"来源：会话推断，已确认"）；推翻时记录用户修正理由。思考链路全程对用户可见，每步大白话。**低置信度推断不得作为建议的唯一依据。** 痛点根因追问链（4.1）与战略/战术利益分层（4.2）的四列推断表、追问链与验证问题 → 详见 reference\03-查表素材.md 第10节「推断规则速查表」。
### 4.3 效益数字三情景推算协议（对应第 5 步"五类量化效益"，数字兜底规则）
五类量化效益每类必须带数字，给不出时按优先级取数、**绝不硬编**：① **取数优先级**：客户实测/历史数据 > 我方资产弹药库案例对标（标"案例外推"）> 三情景推算（标"推算值"）；② **三情景格式**：保守/中性/乐观三档，假设逐条声明（依据是什么、谁负责验证、何时能换成实测值）；③ **纪律**：推算值一律标"（推算值，待验证）"，**不得写成承诺口径进正式汇报材料**——"当场打回"仅适用于连推算假设都给不出的情形，假设给得出就不打回，标置信度继续；全程走通用五步推断（亮链路 + 置信度高/中/低），与 4.1/4.2 同一套标注体系。

## 五、硬要求（方法论明示，违反即打回）

1. **面向高层的价值必须量化**（方法论 Option 03 + 方法论提示"能打动高层，直接对着客户 KPI"）：凡写给一把手看的表述，必须落到数字或明确验收口径。例外口径：数字可经 4.3 三情景推算兜底——"当场打回"仅适用于连推算假设都给不出的情形。
2. **方案须含产品 + 公司 + 销售三层价值**（方法论 Option 02）：缺任何一层的方案价值概述表不予通过。
3. **关注客户业务和各层级 KPI，而不是你的产品**（方法论 Option 01）：输出中产品参数只能出现在第 5 层方案映射和差异对比里；高层叙事线以产品开头 → 打回，改写为从客户 KPI 开头。
4. 每维度配大白话；引用我方资产标注"依据我方资产记忆"；推断亮链路并带置信度——家族共享协议要求，照执行，此处不展开。

### 汇报就绪检查闸门（Go/No-Go，建议上会前必过）
**闸门 6 项**：① 权力者已识别且其 KPI 已量化锚定（第 1 层非空）② 五层地图链条完整（第 5 层可回溯第 1 层，抽查 2 行）③ 一句话核心价值一个呼吸内说完 ④ 五类量化效益带数字且来源可辩护（实测/案例外推/三情景推算之一）⑤ 产品+公司+销售三层价值齐备 ⑥ 三类听众呈现口径已分工——逐项打勾，**任一项"否" → 不得建议上会**，转缺口清单并给补齐动作（"任何一项为否，先别上会"）；逐项勾选明细 → 详见 reference\03-查表素材.md 第11节「汇报就绪检查闸门勾选明细」。

> **提醒项（不阻断 Go/No-Go）**：原"会前准备检查"第 2 项"竞争对手 KPI"表述字迹待核实（见第六节内容警示），暂按"竞争对手 KPI"理解执行；该条降级为提醒，不再列入闸门清单，待用户核实后升级。

## 九、快速速查（口诀保记忆，契约保精确；口诀只索引，条文以各节为准）

**三条命名经验法则**：① "没有数字的 KPI 不是 KPI，是愿望"——对应第 4 步硬性检查与硬要求 1；② "价格不接招，战场搬到老板的目标上"——对应下方决策树；③ "地图断在哪一层，缺口就记在哪一层"——对应缺口转侦察规则。

**健康度红绿灯**：🟢 过闸可上会（生成汇报产物）／🟡 链条有断点或数字为推算值，只内部演练先补缺口／🔴 权力者未识别或 KPI 未量化，禁止上会回决策链破译环节——明细 → 详见 reference\03-查表素材.md 第12节「健康度红绿灯判定」。

**价格战应对决策树**：对手低价、客户动摇 → 权力者已识别？否 → 先补权力者画像（交回决策链破译环节）／是 → 高层 KPI 已量化锚定（第 1 层非空）？否 → 走五层地图建锚点（本 skill 第 4 步）／是 → 价值差距讲得清（五类效益 vs 价差）？能 → 不正面接价，上会讲 KPI（过汇报就绪闸门）；不能 → 移交商机评估，重估这单值不值得打。

现场应对走价格战五步卡：① 钉住现场 ② 命名真顾虑 ③ 给一句可直接说的话 ④ 只用站得住的证据 ⑤ 何时不接 → 详见 reference\03-查表素材.md 第9节「价格战现场应对五步卡」。

**运行示例**：价格战场景完整走一遍（判边界 → 环境自检 → 第 1 层引导 → 逐层走完五层 → 收尾落档）→ 详见 reference\03-查表素材.md 第14节「运行示例」。
