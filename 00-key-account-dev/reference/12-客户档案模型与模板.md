# 12 · 客户档案模型与模板

> **定位**：客户/项目分层档案（L1~L5）的**唯一权威定义**。供全部家族 skill 引用。
>
> **原则**：信息只存一份，存在客户目录里；上下文包只传指针和摘要，不传全量。**L0 已移除**（原"我方企业档案"属跨项目通用信息，已迁入长期记忆·4，见 `11-企业层记忆与参数模板.md`）。

---

## 一、五层模型

| 层 | 内容 | 更新频率 | 对应文件 |
| --- | --- | --- | --- |
| L1 客户主数据 | 集团-工厂层级、组织架构图、战略目标与高层关注、行业与业务信息、与我方历史合作、决策机制 | 低（结构变化才改） | `00-客户主数据.md` |
| L2 人物档案 | 逐人：职务职责、历史背景、汇报关系、五维画像（带日期版本）、接触记录 | 中（每有接触/新情报） | `人物\<姓名-职务>.md` 一人一册 |
| L3 项目档案 | 各 skill 产出（画布/地图/记录）+ 项目执行计划 | 随项目阶段推进 | `项目\<项目名>\01~06-*.md` |
| L4 交互记录 | 拜访、会议、内线消息的时间线流水（append-only） | 高（每次接触即追加） | `交互记录.md` |
| L5 缺口与任务 | 不知道什么、谁去侦察、截止时间（含"前置缺口"：进某环节前必须补齐的信息） | 每次会话收尾更新 | `缺口与任务.md` |

## 三、文件模板

### L1：`00-客户主数据.md`

```markdown
# 客户主数据：<集团名-工厂名>

## 基本信息
- 集团/子公司层级：XX集团 → XX工厂（本档案主体）→ 相关兄弟工厂
- 行业与业务：主营产品、产能、行业地位、近期战略动向
- 工厂概况：产线、主要系统、在用供应商

## 战略目标与高层关注
- 集团/公司战略目标：中长期战略、年度经营重点
- 一把手及高管的公开 KPI 与讲话要点（含来源与日期）
- 业务规划：与高层 KPI 挂钩的部门级规划线索（解决方案设计的顶层素材库）

## 组织架构图
（层级缩进或 mermaid，标注：部门/职务/现任者/分管范围/派系线索）

## 与我方历史合作
- 时间线：接触/合作/丢单记录（链接到 交互记录.md 对应条目）

## 决策机制
- 采购决策流程、评审委员会构成与议事规则（摸清后填写）
- 最近更新：YYYY-MM-DD
```

### L2：`人物\<姓名-职务>.md`（一人一册，维护最重的一份）

```markdown
# 人物档案：张三（分管生产副总）

## 静态信息（变更才改）
- 职务/职责：分管生产、质量管理；兼任技术评审委员会组长
- 历史工作背景：XX 出身、XX 年到现岗位、前任岗位、专业领域
- 汇报关系：向谁汇报、分管哪些部门、与哪些人是老同事/派系
- 个人风格线索：公开讲话风格、口碑
- 表态原话与话术风格：公开表态的原话记录
- 未证实情报：传闻类信息单独记录并标可信度，证实前不进五维画像事实区

## 五维画像（每次决策链破译（02-juece-poyi）分析后更新，旧版本不删）
### 2026-10-19 版
- 马斯洛需求：安全需求（求稳，"只要不出大问题，优先续约"）
- 变革态度：保守
- 决策关注点：业务（"平稳过渡、不影响生产节拍"）
- 联系紧密度：没有联系
- 对我方态度：中立偏谨慎
- 综合判断：权力者，安全需求型，不可催单，需提供"低风险"材料
> 画像置信度：基于 2 条内线消息（见 交互记录 #12、#15）

## 接触记录
- 2026-10-19 通过设备供应商转述得知其对续约的表态（间接，未经证实）
```

**关键规则**：五维画像**按日期版本叠加**、旧版保留——五维的"变化性"本身就是决策链分析的核心洞察（方法论原文：前期安全需求、站稳脚跟后要话语权）。画像是判断，接触记录是事实，两者分开。

## 四、置信度分级（标注到信息条目）

| 级别 | 含义 |
| --- | --- |
| 高 | 用户亲历/正式书面文件/两条以上独立来源印证 |
| 中 | 单一内线来源、间接转述 |
| 低 | 网络公开信息未经核实、AI 推测（必须标注"推测"） |

## 五、维护时机速查

| 时机 | 动作 | 执行者 |
| --- | --- | --- |
| 会话中用户随口给新信息 | 立即写入对应层并口头确认 | 当前 skill（边聊边记） |
| 每次会话收尾 | 落档四件事（L4 追加 / L5 更新 / 画像版本 / 产出落档） | 当前 skill 执行，Gateway 督办 |
| 决策链破译（02-juece-poyi）运行时 | 全量核对人物名单：新名字建册；调离/退休标【历史】 | 决策链破译（02-juece-poyi） |
| 项目进入新阶段 | 项目目录追加该阶段产出文件 | 对应 skill |
| 组织架构变化 | 更新 L1 组织架构图，检查受影响人物画像 | Gateway |
| 定期体检（场景 G3） | 全档案扫描：清理标【历史】信息、提醒超期缺口 | 06-kehujingying |

## 六、信息来源管道

- **用户口述/文档**：直接入档，来源标"用户"；
- **网络公开信息**：必须经用户确认循环后方可采信，来源标"网络：XX（经确认）"；
- **AI 推测**：允许存在但一律标"推测"，且不进 L2 画像事实区，只进"待验证假设"区，证实后转正。

档案条目统一格式：`内容（来源，YYYY-MM-DD，置信度）`。

## 七、附录：纯对话兜底 · 待存档文本块格式样例

运行环境**没有任何持久化通道**时（无文件写入工具、无记忆、无 CRM/数据库连接器），档案职责降级为"输出待存档文本块"（完整触发与处置规则见家族共享协议第六节"纯对话兜底"，按三级回退链读取：**一级**家族根目录 `10-家族共享协议.md`；**二级**本包 `10-家族共享协议.md`；**三级**两者都不可用时按总控路由（00-key-account-dev）的 SKILL.md 与本附录格式执行；与总控路由（00-key-account-dev）的 SKILL.md"档案管理员职责"一致）。收尾时按下列格式逐文件输出，供用户复制保存到本地：

````markdown
# ---- 待存档 · 客户分析\XX集团-某工厂\00-客户主数据.md ----

# 客户主数据：XX集团-某工厂

## 基本信息
- 集团/子公司层级：……
- 行业与业务：……

（其余各层/各文件按同一格式逐块输出）

# ---- 待存档结束 ----
当前为纯对话模式，以上文本块未落盘；请复制保存到对应路径。
下次会话把文本块贴回，即视为有效读档来源。
````

要点：① 每块首行用 `# ---- 待存档 · <相对路径> ----` 注明落点路径，保证贴回时可解析归位；② 明示"未落盘"与"贴回即读档"两点，不让用户误以为已存档；③ 若中途环境获得文件工具，下一轮自动恢复落盘并回告用户。
